# Cognto S&OP Consensus Agent

Read-first, evidence-linked SAP IBP reconciliation copilot for S&OP review step 2BU. This standalone MVP defaults to synthetic data and requires no SAP credentials.

## Run locally

Requirements: Node.js 20+ (no third-party packages required).

```sh
node server.mjs
```

Open http://localhost:4173. To create and verify a production build:

```sh
node tests/run.mjs
node build.mjs
node server.mjs dist
```

## Demo walkthrough

1. Overview opens in synthetic Case A (capacity shortfall), with ranked issue, transparent revenue delta and a human-decision status.
2. Choose Case B in the selector; run analysis; inspect Round 1 and Round 2 in Agent Review and the conditional mix proposal in Consensus Room.
3. Select Case C; verify the coordinator explicitly escalates the incompatible commitment, capacity, and margin constraints.
4. Use Data Workspace to load a customer-authorized CSV extract. The UI validates required fields; uploaded text is treated as data.
5. Inspect Audit Trail and download the JSON executive run package or issue CSV from Executive Pack.

## Architecture

- `src/domain.ts`: typed fact/issue/position/run contracts. `src/domain.js` is the dependency-free browser runtime with deterministic materiality calculations, bounded mock agent rounds, convergence classification, CSV validation and export.
- `src/main.js`: SAPUI5/Fiori-inspired enterprise workbench, scenario selection, data workspace, issue detector, agent review, consensus room, executive pack, audit and settings.
- `src/style.css`: responsive desktop-first Fiori-like visual language based on the existing HPA product patterns: clear shell, navigation, cards/tables, status chips, demo disclosures, and explicit human approval cues.
- `tests/run.mjs`: single-process Node checks for calculation, validation, evidence, convergence/escalation, and CSV export.

The UI runs the domain engine locally in the browser to make the offline demo fully functional. The domain contracts are isolated for extraction into the brief's intended TypeScript REST API and packages (`domain`, `agents`, `ibp-adapters`) as a next deployment packaging step. There is no production LLM call in this build; the deterministic mock provider makes every workflow available without a secret. An external LLM provider must return validated JSON and evidence references before it can replace the mock. No third-party packages are needed.

## Data and calculations

Required CSV columns: `product,location,customer,period,consensusDemand,constrainedDemand,receipts,consensusRevenue,constrainedRevenue,aop,capacityUtilization`. Optional columns: `id,margin,commitment,promotion`.

Revenue delta = consensus revenue − constrained revenue. Revenue delta percentage = delta ÷ consensus revenue × 100. Materiality = min(100, 2 × absolute revenue delta percentage + 30 for utilization above 100% + 15 for a flagged customer commitment + 12 for margin below 20%). Issue inclusion uses the configurable revenue percentage threshold or over-capacity or commitment flag. This is a demonstrator rule set, visible in Conflict Detector; it is not a customer-approved planning policy.

## SAP integration and safety

DemoProvider is active. CSV import is supported. Future `IbpDataProvider` adapters should implement read-only mapping for `/IBP/EXTRACT_ODATA_SRV` and `/IBP/PLANNING_DATA_API_SRV`; production calls remain disabled until approved tenant access and credentials are configured server-side. No SAP write-back, scenario creation, or collaboration post is implemented. Never commit credentials. Uploaded file text is parsed as data only. Human approval in this browser is a local review marker and does not constitute approval in SAP.

## Deployment preparation

The app is a static build suitable for Cloudflare Pages, SAP BTP HTML5 Application Repository, or another static host. Build with `node build.mjs`; deploy the generated `dist/` directory using the hosting provider's project/account configuration. For Cloudflare Pages, set build command `node build.mjs`, output directory `dist`, and use no secret variables for demo mode. Verify the deployed URL and all three scenarios after deployment. No hosting project/account was selected for this task.

## Limitations

- Synthetic cases are illustrative only; no customer outcome, SAP certification, endorsement, or production connectivity is claimed.
- The mock agent outputs demonstrate functional-role positions and evidence links; they are not generated by a language model.
- Browser memory is the run store; refreshing starts a fresh local run. Export JSON to retain an audit artifact.
- CSV parser expects simple comma-separated fields without quoted commas. XLSX and a persisted REST API are not part of this build.
- SAP adapters are documented extension points, not live integrations.
